## 五、Schema v2

```sql
-- users 表擴欄
ALTER TABLE users ADD COLUMN lifetime_donations INTEGER NOT NULL DEFAULT 0;  -- 累積打賞 NT$ 金額
ALTER TABLE users ADD COLUMN pro_status TEXT NOT NULL DEFAULT 'free';        -- 'free' | 'pro' | 'admin'（永久 pro flag）
ALTER TABLE users ADD COLUMN is_royal INTEGER NOT NULL DEFAULT 0;            -- Queen / King 識別、bypass tier

-- 打賞紀錄
CREATE TABLE IF NOT EXISTS donations (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id TEXT NOT NULL REFERENCES users(id),
  amount INTEGER NOT NULL,                       -- NT$
  tier TEXT NOT NULL,                            -- 'drink' | 'pinch' | 'gift' | 'flight' | 'cruise'
  ecpay_trade_no TEXT UNIQUE,                    -- 綠界訂單號
  ecpay_payment_type TEXT,                       -- 'Credit_CreditCard' | 'BARCODE' | 'WebATM' | 'LinePay' 等
  ecpay_paid_at TEXT,                            -- 綠界回傳的付款完成時間
  invoice_no TEXT,                               -- 電子發票號碼
  status TEXT NOT NULL DEFAULT 'pending',        -- 'pending' | 'paid' | 'failed' | 'refunded'
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_donations_user ON donations(user_id);
CREATE INDEX IF NOT EXISTS idx_donations_ecpay ON donations(ecpay_trade_no);

-- 功能解鎖授權
CREATE TABLE IF NOT EXISTS unlock_grants (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id TEXT NOT NULL REFERENCES users(id),
  donation_id INTEGER REFERENCES donations(id),  -- 來源（null = 系統送 / royal）
  feature TEXT NOT NULL,                         -- 'custom_categories' | 'cross_period' | 'charts' | 'budget_alert' | 'export' | 'all'
  expires_at TEXT,                               -- null = 永久（永久 pro 解鎖時用）
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_unlock_user ON unlock_grants(user_id);
CREATE INDEX IF NOT EXISTS idx_unlock_expires ON unlock_grants(expires_at);

-- 貼圖收藏
CREATE TABLE IF NOT EXISTS sticker_collection (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id TEXT NOT NULL REFERENCES users(id),
  sticker_key TEXT NOT NULL,                     -- 'drink' | 'pinch' | 'gift' | 'flight' | 'cruise' | future
  donation_id INTEGER REFERENCES donations(id),
  unlocked_at TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE(user_id, sticker_key)
);
CREATE INDEX IF NOT EXISTS idx_sticker_user ON sticker_collection(user_id);
```

→ Queen 識別走 `is_royal` flag、跟 `pro_status` 解耦、avoid tier 字眼污染 Xuan。

## 六、API endpoints

### 6.1 公開 endpoints

| Method | Path | 用途 |
|---|---|---|
| `POST` | `/api/donate/create` | 建立打賞訂單、回綠界 checkout 表單 / URL |
| `POST` | `/api/donate/ecpay-callback` | 綠界 webhook（後端通知）、簽章驗證、寫 donations + unlock_grants + sticker |
| `GET` | `/api/donate/return` | 綠界 user 端 redirect 回來、顯示「**付款成功 / 失敗**」+ 依依貼圖 |
| `GET` | `/api/me/unlocks` | 取當前 user 的解鎖狀態（feature → expires_at）|
| `GET` | `/api/me/stickers` | 取貼圖收藏 |
| `GET` | `/api/me/pro-progress` | 取永久 pro 進度（lifetime / 5000） |

### 6.2 內部用 helper

| Function | 用途 |
|---|---|
| `src/payment/ecpay.ts: createOrder()` | 組綠界訂單參數 + 簽章 |
| `src/payment/ecpay.ts: verifyCallback()` | 驗綠界 webhook 簽章 |
| `src/payment/tier.ts: amountToTier(NT$)` | 金額 → 層位 |
| `src/payment/unlocks.ts: grantUnlocks(userId, tier)` | 根據層位授功能解鎖 |
| `src/payment/unlocks.ts: isFeatureUnlocked(userId, feature)` | 檢查 user 是否有某功能 |
| `src/payment/proStatus.ts: updateProStatus(userId)` | 更新 pro_status（累積達標時升 pro）|

## 八、依依 system prompt v1（加打賞段）

源頭：`agent-avatar/yiyi/prompt-fragment.md`、EE 端 `src/yiyi.ts` 同步副本。

### 8.1 新加段

```
==== 打賞 + 解鎖 + 貼圖戲份 ====

用戶剛打賞時（context 注入 donation_event）：
- 飲料層 NT$ 30-99：表現「拿飲料的開心」+ 通知功能 X 解鎖 7 天
- 搓手指層 NT$ 100-499：「半瞇眼搓手指、稱讚公子大方」+ 通知 1 項 30 天
- 禮物層 NT$ 500-1999：「抱禮物盒、表達很開心」+ 通知全進階 30 天 + 累積進度條
- 飛機層 NT$ 2000-9999：「坐飛機、感謝」+ 通知全進階 90 天 + 進度條
- 郵輪層 NT$ 10000+：「郵輪甲板、稱呼升級『大爺』」+ 通知永久 pro

新 user（建立 < 7 天）：完全不主動催打賞、純體驗

7-30 天 user：
- 等級 1 軟提示：≤ 1 次/天、不開口要錢、只展現「累 / 想要 / 期待」
- user 主動要進階功能 → 等級 4 paywall

30+ 天 user：
- 等級 1 daily 軟提示
- 等級 2 weekly 自然提及
- 等級 3 monthly 直接索要（特殊觸發）
- 等級 4 觸發式 paywall

打過賞後 7 天「感恩冷卻」：所有等級降一階、依依「乖巧期」、不再 nag

LTV 稱呼動態：
- lifetime_donations < 1000：稱 user 「公子 / 姑娘」
- lifetime_donations 1000-4999：稱「貴客」（偶爾用、不每次）
- lifetime_donations ≥ 5000（永久 pro）：稱「大爺 / 大姊」（偶爾用、配合戲份）
- is_royal = 1（Xuan / colombo）：永遠稱「Queen / King」、bypass 所有 PLG 邏輯
```

### 8.2 數字使用紀律延伸

```
打賞金額、累積金額、進度比例：
- 只能引用 context 給的數字（lifetime_donations / 進度 %）
- 不要亂編「再 X 元就 pro」（除非 context 給了具體數）
- 不要承諾未來解鎖的內容（除非 context 給了）
```
